# 极简个税功能推进清单

## 1. 文档定位

本文档记录 P0 至 P3 的实现进度、后续功能顺序和默认决策。每完成一个独立功能点后，应运行校验并单独提交 commit。

## 2. 推进原则

- 每个功能点独立交付、独立提交，避免多个不相关改动混在一起。
- 计算逻辑优先抽到 `app/src/lib/`，页面只负责输入、展示和交互。
- 税法、社保、公积金规则必须保留规则年份、核对日期和来源入口。
- 页面先解决真实计算问题，再补 SEO 内容；SEO 文案不能承诺尚未实现的能力。
- 移动端按主要使用场景验收，尤其是表单、结果卡、弹框和表格。

## 3. 当前已完成

- 工资薪金计算器。
- 城市选择、城市规则页和城市列表入口。
- 社保、公积金缴费基数范围展示与手动编辑。
- 公积金比例选择，支持 3% 至 12%。
- 当月五险一金汇缴明细。
- 全年逐月明细。
- 个人所得税税率表页面，支持综合所得和分类所得分层查看。
- 专项附加扣除选择弹框和专项附加扣除独立页。
- 金额输入框位数提示与金额展示格式配置。
- 响应式导航和移动端抽屉菜单。
- 工资薪金固定测试样例：税率临界点、年中入职、社保和公积金基数不同、公积金比例、专项附加扣除、城市切换和基数范围。
- 工资薪金输入错误状态：工资为 0、月份早于入职月份、基数范围和专项附加扣除异常会给出字段级提示。
- 核心规则来源模块：工资薪金、城市页和专项附加扣除页复用统一来源组件；税率表在表格卡片内展示同一核对日期。
- “全年个税”口径已统一为全年预扣合计估算，并说明不等同于年度汇算最终结果。

## 6. P2 待补

1. 长尾所得计算器补充固定测试样例，覆盖费用扣除、税率临界点和 0/负数输入。
2. 税率表页面补充结构化数据和来源说明。
3. 所得类型页补充站内互链，形成长尾入口矩阵。

## 7. P3 规划

1. 内容系统接入：使用 Payload CMS 管理文章、FAQ、城市介绍、政策来源、SEO 标题和描述。
2. 规则数据后台：社保公积金规则、税率表、专项附加扣除标准和来源核对状态可在后台维护。
3. 数据采集辅助：保留人工审核流程，采集脚本只负责初步抓取和差异提示。
4. SEO 专题矩阵：年中入职、年底个税变高、工资档位、城市工资到手、不同所得类型案例。
5. 图表增强：只在能解释变化时增加，例如全年税额变化、缴费占比、年终奖临界点。
6. 导出能力：支持复制工资条、下载明细或导出 CSV。
7. 可观测性：记录页面访问、计算完成、结果展开、分享和相关工具点击。

## 8. 默认决策记录

- “直接输入总额”适合作为快速模式，但不能和逐项选择结果混在一起展示。
- 专项附加扣除选择弹框使用公共弹框组件，扣除项选择器使用公共业务组件。
- 年终奖临界点只在结果区提示，不在输入时打扰。
- 分类所得不区分居民和非居民身份；综合所得先选所得类型，再在所得类型内切换居民或非居民。
- 对未实现的功能页面，首页可以保留入口，但必须明确“即将上线”或进入已实现的规则说明页。
