# 个税竞品分析记录

## 1. 文档定位

本文档记录已完成的竞品研究，重点关注工资薪金计算器、城市社保公积金、结果解释和图表能力。

产品总需求见：[极简个税产品需求文档](./personal-income-tax-product-requirements.md)。

本次新增记录的三个竞品：

- [hizdm.cn 北京工资计算器](https://hizdm.cn/city/beijing/)
- [工具派工资计算器](https://gjupai.com/salary-calculator)
- [salarytax 税后薪资计算器](https://salarytax.cn/)

## 2. 结论先行

三个竞品分别代表三种方向：

| 竞品 | 主要方向 | 值得吸收的能力 |
| --- | --- | --- |
| hizdm.cn | 城市规则和五险一金明细 | 城市独立 URL、城市 SEO、基数和个人/企业比例配置 |
| gjupai.com | 全功能薪资分析工作台 | 反向计算、城市范围、全年图表、工资条和方案导出 |
| salarytax.cn | 轻量级税后收入解释 | 结果简单、个人/企业分栏、工资分布和公积金账户入账 |

“极简个税”不应完全复制任何一个竞品，而应组合成：

```text
城市规则可信
+ 输入足够简单
+ 社保公积金允许覆盖
+ 结果能解释变化
+ 图表只服务于理解
```

## 3. hizdm.cn

### 3.1 产品定位

这是一个以城市为核心组织方式的五险一金及税后工资计算器。城市不仅是表单字段，也是页面路径和内容入口。

### 3.2 主要能力

- 城市独立 URL，例如 `/city/beijing/`。
- 有热门城市入口和按省份、拼音组织的完整城市选择页。
- 支持养老、医疗、失业、工伤、生育、公积金等项目。
- 每个项目支持个人比例、企业比例和缴费基数。
- 支持自定义配置。
- 展示个人缴费、企业缴费、个税和税后月薪。
- 展示 1 至 12 月的累计收入、累计五险一金、累计扣除、当月个税和到手工资。
- 提供城市新闻、相关城市和年终奖、工资反推等周边入口。

### 3.3 优点

- 城市 SEO 结构清晰，可以覆盖“北京工资计算器”“上海税后工资”等城市长尾。
- 城市规则和计算结果绑定，用户可以看到社保公积金如何影响到手工资。
- 个人和企业两侧都展示，能满足员工和企业用工成本两种需求。
- 月度明细完整，体现了累计预扣法的全年变化。

### 3.4 问题与风险

- 自定义配置一次展开大量参数，普通用户容易迷失。
- 页面没有把“城市允许的基数范围、规则生效日期、来源”放在最显眼的位置。
- 工资、社保基数和公积金基数的关系解释不足。
- 本次测试中，从北京页面输入工资并计算后，页面出现切换到上海 URL 和标题的情况，需要重点验证城市状态同步问题。
- 页面内容中存在广告和较多周边服务，容易干扰主任务。

### 3.5 对我们的启发

- 城市必须是产品架构的一部分，而不是普通下拉框。
- 每个城市应有独立 URL、独立规则页和独立 SEO 内容。
- 城市选择后，立即展示社保基数范围、公积金基数范围、政策生效日期和来源。
- 城市规则页应支持热门城市、按省份浏览和关键词搜索。
- 个人缴费和企业缴费默认分层展示，企业侧不必占据首屏。

## 4. 工具派 gjupai.com

### 4.1 产品定位

工具派更接近薪资分析工作台，覆盖输入、计算、图表、工资条、年度明细、企业成本和方案导出。

### 4.2 主要能力

- 支持税前转税后和税后反推税前。
- 支持月薪、年薪、年终奖和综合年收入。
- 支持城市选择。
- 社保和公积金基数展示具体范围。
- 支持按工资、最低基数、最高基数快速切换。
- 公积金比例可选；具体选项按页面配置，原型设计中首期确定支持 3% 至 12%。
- 支持专项附加扣除、年终奖单独计税和合并计税。
- 结果包含工资条、年度指标、公司额外成本和用人成本总计。
- 图表包括工资去向环形图、全年走势折线图、月度收入构成图。
- 支持导出 PDF、图片、Excel 和复制分享链接。

### 4.3 图表价值

它的图表不是装饰，而是对应三种理解任务：

| 图表 | 解释的问题 |
| --- | --- |
| 工资去向环形图 | 税前收入最终分成到手、社保公积金和个税的比例 |
| 全年走势折线图 | 到手工资和累计个税在全年如何变化 |
| 月度构成图 | 每个月的工资、扣除和个税如何构成 |

其中，全年走势折线图最值得保留，因为它可以标注税率跨档和个税上升月份。

### 4.4 优点

- 城市、社保范围、收入类型、年终奖和图表连接得比较完整。
- 既能做普通工资测算，也能做不同方案比较。
- “按最低基数 / 按最高基数 / 按工资”降低了手动配置成本。
- 工资条和年度明细让结果更像真实工资核算，而不是一个孤立数字。

### 4.5 问题与风险

- 首屏信息密度较高，输入项和高级能力过多。
- 指标卡、工资条、多个图表、明细表同时出现，容易造成信息过载。
- 登录、保存方案、导出等能力会打断普通用户的基础计算流程。
- “智能推荐”和节税建议需要严格绑定政策版本，不能给出看似精确但缺少条件说明的节税金额。

### 4.6 对我们的启发

- 结果区应有一张“工资去向”图和一张“全年走势”图，但移动端采用切换查看，不同时堆叠。
- 社保基数要显示“城市范围”，并支持按工资、最低、最高和手动输入四种方式。
- 公积金比例应是可选项，首期支持 3% 至 12%，并保留城市规则配置能力。
- 企业成本、导出和方案保存放到结果展开区或 P1，不抢占基础计算首屏。

## 5. salarytax.cn

### 5.1 产品定位

这是一个轻量的税后薪资计算器，重点是让用户快速理解税后工资、个人扣除、企业缴纳和公积金账户入账。

### 5.2 主要能力

- 选择城市或使用自动定位。
- 输入税前月薪。
- 展示税后月薪和公司总支出。
- 按个人缴纳、公司缴纳分栏展示五险一金。
- 使用工资分布环形图解释收入构成。
- 单独展示个人和企业共同缴纳的公积金账户入账金额。
- 基数和比例配置放在二级入口。

### 5.3 优点

- 首屏简单，用户可以快速得到税后工资。
- “工资分布”图表很容易理解。
- “公积金账户入账”是比单纯展示扣款更有感知的结果。
- 个人缴纳、公司缴纳和公司总支出关系清楚。

### 5.4 问题与风险

- 主要是单月估算，全年累计变化较弱。
- 没有充分解释为什么某个月个税会增加。
- 基数和比例隐藏较深，用户不容易确认计算前提。
- 页面年份和规则说明需要持续维护，不能长期固定在旧年份。

### 5.5 对我们的启发

- 首屏可以保留“到手工资”和“工资去向”两个核心结果。
- 可以增加“个人公积金 + 企业公积金 = 公积金账户入账”的解释。
- 图表要服务于结果理解，不为了图表而增加复杂输入。
- 单月结果之外，必须补充全年走势和逐月明细。

## 6. 产品决策记录

以下结论已纳入产品原型和需求：

1. 支持城市选择，并为城市建立独立 URL 和城市 SEO 页面矩阵。
2. 城市选择后展示社保基数、公积金基数的有效范围、规则年度、生效日期和来源。
3. 社保缴费基数默认按城市规则自动估算，同时允许用户手动覆盖。
4. 社保基数和公积金基数分开设置，不能默认使用同一个基数。
5. 公积金个人和单位缴费比例可选择，原型首期支持 3% 至 12%。
6. 手动输入超出城市规则范围时，应提示并阻止静默计算；如业务上允许特殊情况，需要提供“确认按特殊基数计算”的明确入口。
7. 图表首期只保留“工资去向”和“全年走势”两类。
8. “全年走势”优先展示到手工资、当月个税或累计个税，并标记税率跨档月份。
9. 移动端使用“工资去向 / 全年走势”切换，避免多个图表纵向堆叠。
10. 企业缴费、导出、保存方案和多方案对比属于 P1，不占用基础计算首屏。
